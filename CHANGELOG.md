# Changelog

What actually changed in this repo, by day. Not a promise of what's coming, a record of what's real now, same standard as everything else here. See `AGENTS.md` for the procedural rules behind these changes, not restated here. History before this changelog starts lives in `git log`.

## 2026-10-08

**Supernova severed as a source of truth, for components too.** It was already excluded for token existence (`token-api/figma-variables-dump.json`'s own `_comment` documents why); `AGENTS.md`'s `figma`/`supernova` verification rule now applies the same cut to components. Supernova stays valid for exactly one question: does it have its own doc page for something. It's never a stand-in for "does Figma really have this."

**New: `component-api/figma-check.py`**, the component-level counterpart to the existing token-level `figma-check.py`. Checks tracked component-api entries against a real pull of Mozilla's "Nova Styles (Experimental)" Figma file (`component-api/figma-components-dump.json`, via the Runlayer Figma MCP connector), and, new for this repo, keeps a baseline (`figma-components-manifest.json`, `--advance`-gated, same pattern as `check-drift.py`) so a future run reports real additions/removals/renames instead of a flat snapshot.

**`token-api/sync.py`'s token-change report now groups by owning component** (via `token-api/id-map.json`) and annotates each added/changed token with its live Figma match status (via `figma-token-map.json`), instead of printing a flat alphabetical list a human has to manually decode. Caught a real, pre-existing gap doing this: `moz-input-folder` has no entry anywhere in `id-map.json`.

**`textarea`'s `figma` field was wrong** (`"no"`, should've been `"yes"`: Figma has a real "Input Textarea" component). Fixed in `index.html`'s `DATA` array, found via the new component-level checker and confirmed by bug 2075554's upstream commit history.

**Renamed `panel-manager` to `panel-multiview`** (id, display name, and every cross-reference) to match the real upstream class name (`PanelMultiView`) instead of an invented label.

**Five scripts had the same latent bug**, found one at a time while building the above: `check-index-data.py`, `validate-schemas.py`, `update-meta.py`, `build-manifest.py`, and `build-search-index.py` all glob `component-api/*.json` without excluding the two new Figma dump/baseline files, which aren't component entries. One crashed outright, the rest silently miscounted. All five now exclude them explicitly.

**Doc staleness fixes**, from an audit, each independently confirmed before fixing: `README.md`'s regeneration pipeline never mentioned the new `component-api/figma-check.py`; `FAQ.md`'s Supernova entry only described the token-level distrust rule, not today's component-level extension; `component-api/README.md` had a stale arithmetic claim ("57 + 14 = 71 components") against a real current count of 70.

**Writing pass on the Home page:** the "Notes" section, the only generic heading on the whole site, is now "Reading this table," with 2 bullets removed that were pure duplicates of content already in `README.md` and `token-api/README.md`. A cross-reference to the old heading name broke and got fixed in the same pass. Added a "Heads up" banner clarifying this repo is a mirror, not a contract yet (see `AGENTS.md`'s own framing). All `**Warning**`-labeled callouts site-wide (not just that banner) now render with the same yellow treatment, from one shared rule.

**New skill: `/sync-and-drift`** (`.claude/skills/sync-and-drift/`), documenting the real 9-step sync/drift/Figma-check/validate chain as one repeatable procedure, including the rule to never `--advance` a baseline before triaging its diff.

**Full drift triage, all 56 components `check-drift.py` had flagged** (baseline still pinned to a mid-September commit): the overwhelming majority were two repo-wide mechanical sweeps (a TypeScript `tagmap.d.ts` reference addition, and a `default`-export-to-named-export conversion) that touch nothing this schema documents. Real, confirmed documentation gaps, fixed:
- `panel-item` / `panel-list-item`: missing `shortcut` and `aria-keyshortcuts` attributes.
- `button`: missing `ariaSelected` and `buttonRole`, same shadow-DOM-passthrough pattern as the already-documented `ariaPressed`/`ariaChecked`.
- `tab-group`: `TabGroupCreate`'s documented event detail was wrong (`{isAdoptingGroup}`, conditional) against the real, now-always-present `{adopting}`; `TabGroupRemoved`'s detail was undocumented entirely.
- `box-item`: `focus()`'s signature changed and a new public `focusFromEvent()` method was added, confirmed real by checking that `box-group.mjs` now calls it directly, not assumed from the diff alone. Had no `methods` section at all before this.
- `fieldset`: new `inputsRole` property restructures where four already-documented attributes apply, not just one addition. `role`, `ariaLabel`, `ariaOrientation`, and a newly-added `aria-disabled` all move from the outer fieldset onto the `#inputs` container once `inputsRole` is set. Initially flagged as a maybe-not-worth-documenting internal state property; checked the real precedent instead of assuming (`button.json`'s `hasVisibleLabel`/`accessKey`, `panel-list.json`'s `align`/`valign`/positioning flag are all documented internal/state properties), so this repo's convention is to document internal state, not hide it. Fixed all four attribute descriptions plus the new property.
- `tabstrip`: of its 4 new methods, only `openAnimationFinished` is confirmed real public API, found a genuine external caller by searching the whole mozilla-firefox/firefox repo: Firefox's own `BrowserTestUtils.allTabOpenAnimationsFinished()` calls it directly. Added to `tabstrip.json`.

**Punted, revisit on a future sync:** `tabstrip`'s other 3 new methods (`tabAnimationsInProgress`, `markTabOpening`, `cancelTabOpening`) are currently unreachable dead code as of commit `23fd2ecbdb459f63606a188fdea2d4dbee05507c`. Confirmed by fetching the full current `tabs.mjs`: the only thing that ever adds to the private `#openingTabs` set is `markTabOpening` itself, and nothing anywhere in the whole repo calls `markTabOpening` (GitHub code search: `total_count: 1`, just the definition). As a direct result, `openAnimationFinished` (the one real, externally-called method) currently always returns `true`, since `#openingTabs` can never gain a member. This isn't accidental: `markTabOpening`'s own JSDoc ("Marks a newly added tab as opening until `_handleNewTab` runs for it") describes a real intended caller, almost certainly in `tabbrowser.js` or wherever tabs actually get created, a file outside this repo's tracked set. That caller just hasn't landed yet in this commit. Re-check these 3 next time `tabstrip` shows up in drift: once a real caller appears anywhere in the repo, they're confirmed real and should be added; until then there's nothing to document, since they don't functionally do anything yet.

- `stepper`: gained a new sibling prop `activeThemeId`, traced to exactly one real use, sets `data-theme` on the rendered `<main>` when `content.position` is `"card-stack"`. Added. The `content` prop's own shape also grew several new fields this sync (`center_image`, `zap_border_gradient`, new `rtl` override shapes on `logo`/`corner_image`), but itemizing those isn't the right fix: `content`'s existing description is a deliberate, explicitly-non-exhaustive prose sample (it already ends in "and more" and already omits plenty of pre-existing fields like `layout` and `tiles`), so singling out today's new fields for itemization would just be recency bias, not a principled change. Fixed the one real staleness in that prose instead: the `position` enum shown in parens was missing `card-stack` (new today) and `center-large` (missing before today too, noticed along the way). Also noticed `activeTheme`, an existing sibling prop passed right next to the new `activeThemeId`, has no traceable reader anywhere in the file; left undocumented since its actual behavior couldn't be verified, not guessed at.
